# Реестр источников

## Что такое источник

Источник — это **наблюдаемый** канал, за которым мы следим, чтобы находить:

- инфоповоды;
- темы для контента;
- рыночные сигналы;
- аргументы и возражения;
- истории и отзывы;
- идеи для сценариев общения.

Источник — это **не база знаний** и **не источник гарантированной истины**.
Публикации источника не копируются как готовый контент. На их основе создаётся
новый материал, который затем проходит обычную ручную проверку владельцем
(включая Safety Layer, если тема касается дохода, цен, скидок, тарифов, оплаты,
бронирования или доступности).

## Четыре разных состояния — не путать

Это самое важное место документа. Запись в реестре ≠ работающий мониторинг.

| Состояние | Что означает | Где проверяется | Сейчас |
|---|---|---|---|
| **Зарегистрирован** | Источник описан в `config/sources.json` | `load_registry().all()` | 8 источников |
| **Активен** | У записи `"enabled": true` | `registry.enabled()`, `collection_targets()` | 8 из 8 |
| **Есть сборщик** | В коде реализовано чтение этой платформы | `IMPLEMENTED_COLLECTOR_PLATFORMS` | **пусто** |
| **Реально мониторится** | Источник физически читается | — | **ни один** |

`collection_targets()` возвращает **список намерения**: «за этим мы хотим
наблюдать». Это не отчёт о том, что уже собирается.

В этом репозитории кода сбора нет вообще. Control Center читает уже готовые
сигналы из базы Travel Lead Radar в режиме «только чтение». Поэтому шесть
добавленных Telegram-каналов **пока не читаются никем** — они описаны как
намерение и ждут отдельного этапа интеграции со сбором.

## Где хранятся источники

Единственное место — data-файл:

```
config/sources.json
```

Конкретные каналы **не зашиты** в Python. Чтобы добавить, отключить или
переименовать источник, правится только этот файл.

## Формат записи

Файл начинается с версии формата:

```json
{
  "schema_version": 1,
  "sources": [ ... ]
}
```

`schema_version` нужен, чтобы старый код не пытался прочитать файл нового
формата. Загрузчик читает только версию `1`; при большем числе он падает с
понятной ошибкой вместо тихой неверной загрузки. Отсутствие поля трактуется
как версия `1`. Поднимать версию нужно только при несовместимом изменении
структуры — добавление новых полей к источнику этого не требует.

Сама запись источника:

```json
{
  "id": "telegram_example",
  "name": "@example",
  "platform": "telegram",
  "username": "example",
  "url": "https://t.me/example",
  "source_type": "monitored_source",
  "purpose": "content_and_business_signals",
  "enabled": true,
  "priority": 50,
  "notes": "Свободный комментарий"
}
```

| Поле | Обязательно | Описание |
|---|---|---|
| `id` | да | Уникальный технический идентификатор |
| `name` | да | Человекочитаемое имя |
| `platform` | да | `telegram`, `vk`, `rss`, `web` — список расширяемый |
| `url` / `username` | да (одно из) | Адрес источника |
| `source_type` | да | Категория: `monitored_source`, `reviews_and_stories`, `own_web_resource`, … |
| `purpose` | да | Для чего наблюдаем источник |
| `enabled` | нет (по умолчанию `true`) | `false` — источник не участвует в сборе |
| `priority` | нет (по умолчанию `50`) | Меньше число — выше приоритет |
| `notes` | нет | Заметки |

Для Telegram достаточно указать любой из вариантов: `example`, `@example`,
`t.me/example` или `https://t.me/example/123`. Реестр сам приводит запись к
username `example` и каноническому URL `https://t.me/example`.

Недопустимые Telegram-адреса реестр отвергает при загрузке, а не «угадывает»:
приватные приглашения (`t.me/+hash`, `t.me/joinchat/...`), чужие хосты
(`https://evil.com/t.me/x`), схема `tg://` и имена с недопустимыми символами
дают ошибку `SourceRegistryError`. Молчаливая догадка была бы опаснее ошибки:
она превратилась бы в канонический `https://t.me/<чужой-канал>`.

Неизвестные дополнительные поля (и у источника, и на верхнем уровне файла)
загрузчик игнорирует. Опечатка в названии поля не может тихо отключить
источник: отключает только явное `"enabled": false`.

### Платформы расширяемы, но платформа ≠ сборщик

Новое значение `platform` (`youtube`, `dzen`, что угодно) не требует изменений
Python-кода: загрузчик примет его и не упадёт.

**Но появление платформы в реестре само по себе не создаёт для неё сборщик.**
Это только запись о намерении наблюдать. Список платформ, для которых сбор
реально реализован в этом репозитории, — `IMPLEMENTED_COLLECTOR_PLATFORMS` в
`app/services/source_registry.py`; сейчас он **пуст**.

Известные платформы в `app/domain/sources.py` — это только константы и защита
от опечаток в тестах, а не перечень поддерживаемого сбора.

## Как код получает источники

```python
from app.services.source_registry import collection_targets

for source in collection_targets(platform="telegram"):
    ...  # source.target -> https://t.me/<username>
```

- `collection_targets(...)` — единственная точка входа для кода сбора.
- Возвращаются **только активные** источники: запись с `"enabled": false`
  не попадает в выборку никогда.
- Можно фильтровать по `platform` и по `source_type`.
- Возврат источника отсюда означает «должно собираться», а не «уже собирается».

Полный API — `app/services/source_registry.py`:
`load_registry()`, `SourceRegistry.all() / .enabled() / .disabled() / .get() /
.by_platform() / .by_source_type()`.

## Просмотр реестра

```powershell
.\.venv\Scripts\python.exe scripts\list_sources.py
.\.venv\Scripts\python.exe scripts\list_sources.py --platform telegram
```

Скрипт только читает и печатает. Он ничего не собирает, не ходит в сеть и не
меняет файлы. Полноценное управление источниками через интерфейс — отдельный
будущий этап.

## Границы текущего этапа

- Сам сбор данных живёт в отдельном проекте Travel Lead Radar. Control Center
  читает уже подготовленные сигналы из `leads.db` в read-only режиме.
- Реестр задаёт **что наблюдаем по замыслу**; он не запускает сбор сам по себе
  и ничего не мониторит.
- Интеграция реестра с Travel Lead Radar — отдельный следующий этап. Она
  ещё не сделана.
- Админки и UI управления источниками сейчас нет — это отдельный этап.
